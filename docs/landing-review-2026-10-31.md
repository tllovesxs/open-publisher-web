# 稿流官网定向优化与验收

## 方向与依据

保留稿流、React/Vite、深色背景、原主标题及已有业务路由。将“资料逐步成为成稿”作为页面的视觉内容：同一篇文章的资料摘录、大纲、正文、修改理由、配图与图注取代抽象装饰。

已阅读 design-taste-frontend、impeccable 及相关参考，执行 context、方向抽取、lint、浏览器 inspector 与截图复核。目标仓库及工作区根目录没有 PRODUCT.md / DESIGN.md，未假设它们存在，也未用其他蓝本的同名文档代替。方向采用 editorial-report，保留品牌色与字体；界面片段使用真实内容。

## 改动

- 用途说明在标题后、按钮前；桌面左右布局提前展示产出，手机顺序为标题、用途、开始创作、示例。
- 首屏仅一个主按钮；导航登录与示例入口为弱入口。移除大面积紫色渐变、光晕、星形与装饰网格。
- 四阶段围绕项目公共文章《把零散想法变成一篇清晰的文章》，正文保留原文，研究、编辑与配图明确标示演示。
- 阶段采用 tablist/tab/tabpanel、方向键及 Home/End、清晰焦点。默认不播放；主动播放每 9 秒切换，手动选择停止播放；支持暂停、系统减少动态效果、页面隐藏与离开视口时停止推进。
- 通过 CSS 重叠网格预留最长阶段的高度，隐藏阶段不可见且不可聚焦，避免切换推动阅读位置。
- 三个能力区分别提供资料到大纲、同段不同表达、图文编排证据；相邻构图变化。工作流程仅描述用户操作。
- 完整原文直接从已有 backend/app/data/example-article.v1.md 构建导入，可在官网展开阅读，不依赖后端在线。
- 图示为原创说明图；手机采用纵向构图，避免缩小桌面图中文字。
- FAQ 只描述代码确认的登录、资料格式、复制正文与扩展草稿同步条件。

## 产品事实

来源：CreatePage.tsx、ArticlesPage.tsx、SyncPublishDialog.tsx、backend/app/data/example-article.v1.md 与 examples.v1.json。

- 发起 AI 创作需要登录与配置模型服务。
- 文件输入支持 .md、.markdown、.txt，也支持图片与素材引用。
- Markdown 编辑、预览、审阅、配图、模板及素材入口已实现。
- 同步依赖浏览器扩展与平台已登录账号，仅提交草稿，后续发布由用户确认。
- 未添加用户数量、评价、效率数字、平台名单、免费或价格承诺。

待确认：PDF/Word 等文件导出入口与支持范围、收费/额度政策、扩展支持的平台与移动浏览器兼容性。页面没有承诺上述未知能力。

## 验收与限制

生产构建包含 TypeScript 检查。Playwright/Edge 在 1440、768、390 下核验：标题两行、说明在 CTA 前、无横向溢出、图片加载、阶段高度与滚动位置稳定、ARIA 关联、方向键/Home/End、焦点、风格切换、FAQ、锚点避让导航、播放/暂停/手动停止、减少动态效果和工作台往返。

现有本地后端数据请求不可用，文章库、模板、素材路由可进入但出现数据加载失败。官网示例已独立可读；本轮未验证真实模型生成、登录账号、平台扩展同步和文件导出。未进行屏幕阅读器、真实手机/触摸设备或五秒用户理解度实验。不要将布局检查等同于转化效果证明。

taste lint：0 FAIL，保留既有 Inter 字体警告；impeccable detector：同一字体警告。浏览器 inspector 的人工解释：still-page（默认静态与用户主动播放符合本次阅读需求）、eyebrow（误认主操作旁的示例链接）、reduced-hidden（误认互斥标签页的非当前面板）。不为评分额外添加装饰动效。照片与视频警告：产品以具体界面和真实正文为证据，不存在可用真实操作录像；不以无关图库填充。measure/off-centre 为中文和界面片段探测结果，已按截图检查实际正文宽度和共同对齐。

工具对内部滚动容器只截取一屏，因此补充 Playwright 按区块滚动截图，未仅依赖工具的“整页”结果。Vite 的既有 Mermaid 大分包警告仍存在。
