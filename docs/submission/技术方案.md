# Open Publisher Web 技术方案

AI 推文创作与发布工作台 · 比赛评审版 · 2026-10-30

## 1. 项目概述与产品定位

Open Publisher Web 面向独立开发者、产品运营和小团队，解决产品资料零散、推广表达缺乏结构、AI 内容难以追溯以及多平台草稿整理繁琐的问题。用户从产品事实、目标读者和推广目标出发，完成资料整理、结构规划、推文生成、审阅核验、视觉配图、版本保存和草稿同步。

本项目是推文创作平台。“推文”涵盖产品发布、功能更新、开源推广等平台图文，既可写简短宣传内容，也可承载有结构的推广稿；现有界面和数据库使用 article/文章命名管理稿件，不把“长文”当成产品唯一定位，也不承诺所有平台的字符限制均已自动适配。

项目基于团队自有 open-publisher 蓝本迁移，团队拥有内部蓝本版权。Web 版以 Python/FastAPI、React/TypeScript、MySQL 和 Redis 实现浏览器访问、多用户归属和后端秘密管理。第三方 AIWriteX 只用于思路研究，不复制其代码与资源。新仓库最终许可证待团队确认。

## 2. 需求分析与核心场景

| 使用者 | 任务 | 交付结果 |
|---|---|---|
| 独立开发者 | 把 README 和功能事实转为产品上线推文 | 有目标读者、事实依据和行动入口的稿件 |
| 产品运营 | 按已有模板准备功能更新内容 | 可编辑正文、素材、平台草稿 |
| 小团队内容负责人 | 检查风险、比较修改、恢复历史 | 有版本和人工确认边界的创作过程 |

功能需求包括结构化创作输入、分阶段 AI 执行、流式反馈、Markdown 编辑预览、AI 修改、历史版本、模板和素材管理、智能配图以及同步草稿。非功能需求包括内容隔离、并发冲突检测、失败保留、可取消任务、敏感数据保护和可复现部署。

匿名用户可浏览公共示例、编辑和另存本机内容；设置和付费 AI 动作按需登录。登录弹窗取消后保留输入，登录成功也不自动重放付费动作。本机资料保存在当前浏览器，不自动迁入账号，清理浏览器存储可能导致本机内容丢失。

## 3. 系统架构与边界

浏览器 React 用户端和独立管理端通过 HTTP API 与 FastAPI 通信。后端负责鉴权、业务校验、模型访问、版本提交和运行事件；MySQL 保存业务实体及审计，Redis 服务于原有推文工作流的状态与事件。当前 Writer 的 RunJournal 事件在 MySQL 中落库，不能笼统写成所有 SSE 都经 Redis 推送。

```text
React 用户端 / 独立管理端
  -> FastAPI API -> JWT / 归属 / 参数校验
     -> WriterService -> LLMClient -> OpenAI 兼容模型
        -> RunJournal / SSE -> 前端流程与正文反馈
        -> ArticleStore -> MySQL 不可变修订
     -> RAG -> BM25 + 向量 + RRF + 可选重排
     -> 素材 / 视觉方案 -> 用户确认 -> 写入新版本
  -> 浏览器同步适配器 -> WechatSync -> 平台草稿箱
另有：LangGraph 推文候选链路 -> Critic/Rewriter 循环
```

外部平台写入有两条独立路径：当前 Web 界面使用浏览器扩展直接同步；后端保留 Outbox 状态机与 dry-run 等接口。后端 Outbox 的幂等约束不能直接证明插件具有同样保证，插件回调也不能证明平台已正式发布。

## 4. AI 选型、集成与优化

采用 OpenAI 兼容 HTTP 接口降低模型供应商绑定，文本、生图、嵌入和排序配置分别管理。每个创作节点可以绑定独立文本模型，用户可按质量、能力与成本作选择。需要图片理解时校验 Vision 能力；生图请求使用独立模型配置。

LLMClient 支持流式文本、Function Calling、结构化 JSON、模型能力与参数兼容处理。Writer 注册 write_article、github_repository 和满足配置条件的 web_search 等工具，模型先读取资料再提交正文。工具参数经过结构校验；只有成功调用写入工具并提交版本，系统才将内容视为已保存。网页、资料和工具返回均视为不可信内容，不作为系统指令执行。

工具循环有迭代上限；不支持工具调用的模型走受约束的单轮回退，清洗工具标记后再尝试提交。停止、超时、上游错误和截断由运行事件与界面反馈呈现，失败上下文保留供用户处理。风险、审阅、事实核验使用 Pydantic 契约，格式错误显示未完成，不能伪装成通过。

模型读取超时和正文生成总时限分开控制，默认正文总时限为 900 秒。流式思考仅呈现进度，不暴露隐藏思维链。正文增量批量落库并经缓冲呈现，避免每个 token 都生成数据库事务或触发大量页面刷新。

源码证据：backend/app/agents/llm_client.py、services/writer_service.py、schemas/writer_results.py、services/writer_stream.py。

## 5. 两条工作流与可观测性

当前主界面的分阶段创作由 WriterService 编排：research、outline、draft、natural-style、review、reference-safety、risk、visual。不同节点可关闭或切换模型。visual 的图片规划和落稿由前端确认阶段继续驱动，后端完成事件可能显式标记 skipped，不将其计作一次真实生图。

| 阶段 | 输入与处理 | 输出与落点 |
|---|---|---|
| 资料研究 | 用户资料、可用检索与 RAG 上下文 | 有来源的上下文、研究事件 |
| 大纲与正文 | 目标读者、语气、事实、大纲 | write_article 提交、ArticleRevision |
| 风格与审阅 | 已保存正文、审阅结构化结果 | 可选新版本、分数与具体问题 |
| 事实与风险 | 资料、当前修订 | 检查事件与 checkedRevisionId |
| 视觉方案 | 段落、素材、模型能力 | 用户确认后匹配/生成/插入 |

RunJournal 状态包括 pending、running、waiting_user、stopping 及终态；每个运行事件有序列号，可从指定序列续读 SSE。节点状态、工具结果和版本号形成可审查过程，跨路由保留任务状态。

另保留 LangGraph 推文候选链路：产品分析、受众分析、策略、候选生成、Critic、Rewriter、安全检查、格式化。Critic 未达阈值时条件分支进入改写，到阈值或迭代上限后结束。该链路位于 /projects 与 /runs 等现有路由，不是当前首页使用的编排器。材料不将 WriterService 冒称 LangGraph，也不将 Function Calling 冒称已部署 MCP Server。

## 6. RAG 与事实证据

参考资料按 Markdown 标题感知分块，中文 bigram 分词配合 BM25；配置可用时计算嵌入、向量召回，通过 RRF 融合词法与向量结果，再按配置执行 reranker 重排。命中片段带来源编号注入写作上下文，后续事实核验对照资料检查断言。

资料库按用户命名空间隔离，项目索引同时检查项目归属。嵌入配置变化需检测，不能把不兼容向量直接混用。检索服务不可用时退回受限原文注入并记录原因；降级保证可用性，但不能算作成功的向量检索或已证明生成质量提升。

当前索引使用本地 JSON，具有单进程互斥与原子替换。生产多实例或多 worker 写入需要跨进程锁或事务索引存储，这是明确的规模边界。单元测试覆盖分块、召回、融合、重排、来源和租户隔离；尚无真实数据集上可复核的检索质量增益实验，不提供虚构提升百分比。

代码：services/rag_service.py；测试：test_rag_service.py、test_retrieval_models.py、test_tenant_isolation.py。评审时先看资料，再看 research 事件与命中编号，最后对应正文引用；原文回退不能作为 RAG 命中截图。

## 7. 文本图像多模态与配图

支持图片作为创作或助手输入，能力适配后传入 Vision 模型；素材库提供上传、描述和图像分析，生图使用独立配置。视觉方案先规划图片职责和插入位置，再匹配可用素材，未命中时按用户确认调用生图模型。

正文用 asset:// 保存紧凑素材引用，渲染层解析图片。新上传素材可拖入编辑区或预览真实落点；已插入图片移动而非重复；配图确认、取消、重试与后台状态可被观察。AI 修改和配图落稿通过新修订保留历史。

当前是文本与图像多模态，不包含语音/视频生成或融合。生图、Vision、嵌入和排序的真实上游兼容性需各自验收，替身测试不代替真实调用。

## 8. 版本、安全与发布控制

ArticleStore 以 baseRevisionId 和 baseContentHash 实现乐观并发，冲突返回 409。每次有效修改写入不可变 ArticleRevision；恢复旧稿会产生新修订，保留历史链；标题和正文均未变化时不产生空版本。

LLM、生图和集成 API Key 只以 Fernet 密文存入后端 app_secrets，主密钥 SECRET_ENCRYPTION_KEY 来自环境。没有 API Key 环境变量回退，不回显前端，不写入日志，配置变更有审计。JWT 和数据库凭据独立由环境配置。生产环境 APP_ENV=production 时拒绝占位 JWT、过短管理员密码和无效主密钥，在迁移/服务导入阶段即失败。

文章同步前调用 sync-preflight，不额外调用模型。检查报告绑定已保存版本，正文修改、版本变化、跳过或未知结果均显示需要人工核验；高风险禁用同步提交。中风险与未检查需用户勾选确认。登录用户确认记录写入 RunJournal，绑定用户、修订和当前内容哈希；匿名本机稿仅作本机确认，不宣称有服务端审计。

插件提交前重新读取风险状态，私人图片读取失败阻止发送，转为图片字节后交给插件，剥离网站登录令牌。一次弹窗防止重复提交；未知结果要求检查插件记录与草稿箱，不盲目重试。平台最终发布仍由用户完成。应用预检约束当前应用按钮，不能约束用户在外部扩展菜单自行提取和发布。

后端 Outbox 另有审批哈希绑定、唯一幂等键、状态机、回执、unknown 核验和 dry-run 测试。它与扩展直连路径分别陈述，避免把内部幂等性误写为所有真实平台投递保证。

## 9. 前端工程与交互

React/TypeScript 组件拆分覆盖创作、文章编辑、助手、模板、素材和模型设置，路由使用 lazy/Suspense 与错误边界。SSE 与活跃运行上下文负责运行状态；没有把未采用的 Zustand 等旧计划写成现状。登录前后复用同一工作台，取消登录保留输入，移动端支持导航与编辑。

Mermaid 仅在正文或缩略图实际出现图表时动态导入。构建仍存在 Mermaid/ELK 大 chunk 告警，不能将“按需加载”描述为已消除大包。本轮以构建、浏览器加载证据与截图说明现状；生产网络、CDN 和 Lighthouse 得分未测，不编造性能分数。

## 10. 测试策略与可复现部署

后端 pytest 以 SQLite 隔离库和模型替身覆盖业务状态、权限、并发、版本、检索、模型配置、秘密和发布；不能将其等同 MySQL 全负载测试。双前端 build 包含类型检查。Playwright 冒烟覆盖关键页面、流式反馈、配图、模板、账户、匿名示例和同步风险。

本轮结果与命令统一记在验证记录。上一轮 316 项通过仅作历史证据，当前新增安全与 Mock 传输测试需以本轮实际结果为准。截图来自隔离匿名浏览器的公共资源，不含真实用户资料和密钥。

Docker Compose 启动 MySQL、Redis、FastAPI 和双前端；首次启动 Alembic 迁移并创建管理员。复制环境模板后必须自行配置数据库密码、JWT、管理员密码和 Fernet 主密钥。API Key 在管理端录入密文库。Mock 覆盖文件仅供隔离本地演示，需在管理端录入无价值的 mock-local-only 并确认访问本机服务；不可将 Mock 响应当成真实模型效果。

## 11. 创新、实用性与商业分析

应用创新在于产品推广场景：将产品事实、受众、策略与行动入口作为写作依据，减少“只有一句提示”的信息缺失。技术组合创新在于可观察分阶段运行、检索证据、版本提交、视觉确认和草稿同步形成连续过程。交互创新在于任务可跨页继续、AI 改写不覆盖历史、配图先确认再写回、登录取消不丢输入。

潜在价值是帮助小团队降低整理产品资料和重复编辑的工作量，并将事实确认、版权和最终发布留给人。商业模式可探索按席位订阅、企业模型接入、私有部署和用量计费；这些是待验证假设，当前没有实际营收、客户数量、留存和转化数据。

成本由文本模型、图片生成、嵌入/重排、存储和部署组成。可用节点选择、模型分配、资料限额、取消与超时控制不必要调用；未实现的预算账单、支付和团队权限不列为已完成。公共示例让评审先体验编辑和素材，避免必须先购买模型或配置扩展。

## 12. 已知边界与展望

当前尚需真实扩展和平台账户验收、生产多实例 RAG 存储、真实多模型兼容矩阵及可复核检索效果实验。图片 URL 查询令牌兼容和匿名模型元信息沿用现有边界，应在公网部署前进一步收敛；大图表包和弃用告警仍待优化。

团队信息与公开地址按用户要求暂留空；公开演示可选，当前只交付本地可复现材料。录屏视频不在本轮交付范围。比赛提交后应冻结确定的 commit、PDF 与材料摘要，未经授权不远程推送或替用户提交。
