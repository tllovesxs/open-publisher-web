# 功能与评分证据

评分权重依据工作区 WORKLOG.md 中登记的赛事标准。源码路径以 backend/app/ 为基准，后端测试位于 backend/tests/，前端组件位于 frontend/src/，浏览器脚本位于 frontend/scripts/。

| 维度 / 细项 | 权重 | 实现与证据 | 展示重点 |
|---|---|---|---|
| AI：模型集成 | 8% | agents/llm_client.py、schemas/writer_results.py；test_llm_compatibility、test_writer_stream | 流式响应、参数适配、结构化结果校验 |
| AI：Agent 与工作流 | 8% | services/writer_service.py、run_journal.py；test_writer_pipeline、test_graph | Writer 分阶段编排、工具写入、版本事件与 LangGraph 候选改写 |
| AI：RAG | 6% | services/rag_service.py；test_rag_service、test_retrieval_models、test_tenant_isolation | BM25、向量检索、RRF 融合、重排与来源编号 |
| AI：多模态 | 5% | 图片输入、Vision 能力校验、visual_planning_service.py、image_service.py；test_visual_pipeline、test_image_blueprint | 图片理解、素材匹配、配图规划与确认落稿 |
| AI：安全可控 | 4% | secret_box.py、publish_safety.py、SyncPublishDialog.tsx；test_secret_store、test_release_safety、smoke-sync-safety | 密钥加密、风险分级、版本绑定与人工确认 |
| AI：MCP 或工具 | 4% | Writer 工具注册、参数 schema、工具结果闸门；test_writer_pipeline、test_mock_transport | Function Calling 将模型输出写入稿件版本 |
| 创新：选题 | 10% | 产品事实输入、受众与目标、推广模板 | 将产品信息转为面向目标读者的推广内容 |
| 创新：技术组合 | 8% | 资料研究、结构规划、正文生成、核验、视觉与版本管理 | 串联创作过程，各阶段结果可查看、可编辑 |
| 创新：交互模式 | 7% | 按需登录、跨页运行、配图确认、版本恢复 | smoke-workspace-login、smoke-visual-plan、smoke-image-drag |
| 工程：TS 与代码 | 4% | TypeScript 类型检查、双前端 build、后端 pytest | .github/workflows/quality.yml 与回归结果 |
| 工程：组件架构 | 3% | article 组件、ActiveRunProvider、VisualPlanProvider、路由错误边界 | 前后端职责清晰，创作状态由共享上下文管理 |
| 工程：性能 | 3% | 路由 lazy、图表动态导入、正文增量批量写入 | 本地生产构建首屏 5 个脚本、98,102 bytes，图表引擎请求为 0 |
| 实用性 | 10% | 产品发布、功能更新、模板复用、素材与草稿同步 | 从资料输入到可编辑稿件的完整操作过程 |
| UX：视觉 | 4% | 共用工作台、明暗主题、390px 布局 | screenshots/01-06 展示桌面与移动端 |
| UX：反馈与导航 | 3% | 加载状态、取消保留输入、按需登录、操作反馈 | smoke-ui、smoke-workspace-login、smoke-account-menu |
| UX：AI 交互 | 3% | 节点进度、SSE、停止、结构化报告 | smoke-writer-stream 与运行记录 |
| 社会价值与商业 | 10% | 资料、模板、素材、版本在团队创作中复用 | 减少重复整理与编辑操作，支持小团队内容运营 |

## 验证方式

后端测试采用隔离数据库与模型替身，Mock 协议测试使用本机 HTTP 服务。浏览器脚本验证工作台交互与状态流转，界面截图采集自本地公共示例。性能数据的环境与样本见验证记录。
