# 部署、验收与提交清单

## 本地启动

1. 安装 Docker / Compose；检查 5173、5174、8000、33061、6379 端口。
2. 复制 .env.example 为 .env，设置数据库密码、JWT、管理员密码和 Fernet 主密钥；不要提交 .env。
3. docker compose up -d --build；启动自动执行 alembic upgrade head。
4. 检查 GET http://localhost:8000/api/health，status/database/redis 均正常；访问用户端与管理端。
5. 在管理端录入模型与集成 Key，API Key 只加密入库；无 API Key 环境变量回退。

生成本地秘密时可使用 Python secrets.token_urlsafe(48) 和 Fernet.generate_key()，仅保存在自己的环境中；不要将生成输出复制到公开材料、截图或日志。

## 公网部署前

- APP_ENV=production；JWT 至少 32 字符，管理员密码至少 12 字符，拒绝 dev-/change_me/changeme 前缀；主密钥必须是有效 Fernet Key。校验在 get_settings 首次导入时运行，迁移与服务会及早失败。
- 显式设置数据库强密码，数据库/Redis 不对公网暴露，后端与双前端通过 TLS 反向代理访问；当前 Compose 是本地开发拓扑，不能直接视作公网生产加固。
- 配置实际同源 API 与 CORS；不要沿用管理端 localhost API 地址；验证同源 Cookie、图片授权和代理日志脱敏。
- MySQL 与 SECRET_ENCRYPTION_KEY 分别备份；丢失主密钥会使既有密文不可解密。
- 当前 RAG 只部署一个写入进程；多实例改用事务索引或跨进程锁后再验收。
- 配置额度与专用账号，避免评审误用管理员；真实 Key、用户正文、令牌不进入公共截图。

python -m pytest tests -q -p no:cacheprovider
# frontend 与 frontend-admin 目录各执行

## 提交冻结

| 状态 | 内容 |
|---|---|
| 已补 | 技术 Markdown、PDF、评分矩阵、评委指南、演示脚本、截图、验证记录 |
| 已补 | 生产设置校验、当前应用同步前风险检查、确认审计、Mock 协议 |
| 暂不填写 | 团队名称、成员分工、联系方式、公开地址、评审账号 |
| 本轮排除 | 视频录制与剪辑 |
| 尚需落实 | 公网持续可用性（可选）、真实上游专项验收、最终提交版本冻结 |

冻结时选择干净 commit，记录 git rev-parse HEAD、PDF SHA256、环境依赖及材料列表。保留完整开发历史；提交后不改提交版本。生成包应排除 .env、数据库、模型档案密文、临时 work/、node_modules、日志和私人截图。不要通过 git add . 将未知文件混入材料。

本地 commit 按项目规范执行；远程 push、比赛提交、真实平台发布分别需要用户明确指示。本轮不执行它们，也不擅自决定团队许可证。
